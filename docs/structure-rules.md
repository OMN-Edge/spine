# The structural rules

What "clean" means in this repository, as rules that a machine checks. Before this page, "clean" meant whatever the person reviewing thought of last, and the same kind of problem was found again and again (a server that could hold records because one entry point forgot a setting; a build that swapped files by path; a relay that crashed on start with every test green). A rule is only here if it came from a real failure and has a check that fails when it is broken. [`core/src/__tests__/architecture.test.ts`](../core/src/__tests__/architecture.test.ts) holds the ones that can be read from the code, `server/scripts/smoke-entrypoints.mjs` starts every process, and CI runs both.

A change that needs an exception edits the list in the test and the table at the end of this page in the same commit, and says why.

## The rules

| | Rule | Why it exists | Checked by |
|---|---|---|---|
| **S1** | **Direction.** `core` imports nothing from `server` or `web`. They reach it as `spine-core/...`, never by path. Production code does not import test code. | One shared package, two hosts; a path into the other side is a dependency nobody declared. | `architecture.test.ts`, `boundary.test.ts` |
| **S2** | **Core is platform-neutral.** It imports only its own files, the third-party packages on a list in the test and, from Node, `path` (pure string functions). No native library, no program, no vendor SDK. (`Buffer` is a global, not an import: see E2.) What else it needs from the machine it asks for through a port. | Node-only code had to be swapped for the device by a map of file paths, and a new file could slip in unnoticed. | `architecture.test.ts` (an allowlist: a new import fails until someone adds it, here) |
| **S3** | **Nothing is wired by default.** Every capability a host brings (the store, the SQLite driver, who a request is from, the files, the hashing, the settings, the native tools, the model providers) is registered at that host's entry point, and a process that did not register one fails at its first use, naming it. A capability that is optional (`ShareHost`) is null on purpose, and null means off, never permissive. | A default store scope held records on the server when an entry point forgot to say; a default driver and a default provider were the same mistake waiting. | `architecture.test.ts` (each port fails closed), `ports.test.ts`, the smoke test |
| **S4** | **A host gets the least its type allows.** The server's store has no repository of records, so server code cannot reach one. | A runtime flag that swapped repositories for ones that throw was a rule only a test could keep. | `boundary.test.ts`, `accounts-scope.test.ts` |
| **S5** | **One door per engine and vendor.** The name of an engine (SQLite) or a vendor appears only in its adapter and in one assembly file per host. | The device's start-up read the engine's change counter and handled its database handle. | `architecture.test.ts` |
| **S6** | **Production ships production.** The build output and the images hold no test, no test helper and none of the Node tools that exist to run the app in tests. | The images carried 1.1 MB of compiled tests. | `architecture.test.ts` (build configs, Dockerfiles) |
| **S7** | **No hidden build-time substitution.** The device's build may alias only the packages on the list in the test. It never swaps a file by its path or turns a package into an empty module; output is built from an empty folder; the worker is one file. | A map of paths, empty-module aliases, stale output that made a broken import look fine, and chunk order that stopped the core starting. | `architecture.test.ts` (the alias list), `web/scripts/check-bundle.mjs` (the build runs it), `npm run build` clears `dist` |
| **S8** | **Every process is started by a test, as deployed.** Each entry point is composition: it registers what the process uses, then starts, in an order that matters and that no unit test runs. | The relay asked for its model client before registering a provider and crashed on start, every test green. | `server/scripts/smoke-entrypoints.mjs` (run by `check.sh` and the Dockerfiles), `architecture.test.ts` (the list is complete) |
| **S9** | **Failure is visible.** Work that holds a person's data is not dropped or hidden: a failed save is kept and retried and shown, locking over unsaved changes is refused, best-effort work logs why it failed. | Drained changes were lost when an upload failed, and the page believed it had saved. | `persist.test.ts`, `boot.test.ts`, `client.test.ts`, `check:app` |
| **S10** | **Inputs are reproducible.** One lockfile, `npm ci`, container images named by digest. | A regenerated lockfile moved a bundler and the worker stopped starting. | `pinned-images.test.ts`, `architecture.test.ts` |
| **S11** | **A rule is a check.** A rule with no check that fails is a wish, and it goes in neither this table nor the code. | This page did not exist. | this table |
| **S12** | **Documents name only what exists.** A file path, environment variable, function or type, or relative link (and its heading) in backticks or a link in the docs is in the repository. Prose is not checked, so a claim about behaviour still needs a person; the names inside it do not. | Each review found names the code had since lost (a route, a file, a port), because nothing compared them. | `core/src/__tests__/docs.test.ts` (names that are meant to be absent are listed there with the reason) |
| **S13** | **Nothing runs only in tests, and what people agree to cannot change quietly.** A production export that no production code refers to (comments do not count) is listed as a test helper with its reason, or it fails; a runtime dependency is named in its package; a screen string that says "the server" was reviewed; a document cites no line number; and a text in `docs/legal/` cannot change unless its version is raised and recorded. | A start-up function with a test and no caller did nothing for a long time; screens said the server did what the device does; texts were rewritten with no new version. | `core/src/__tests__/hygiene.test.ts`, `legal-texts.json` |

## Where the rules are known not to hold, and why

These are exceptions, each with a reason and the check that bounds it. They are decisions, not oversights; changing one is a project, not a fix.

| | Exception | Why it is accepted | What bounds it |
|---|---|---|---|
| **E1** | Model clients, the embedder and the parser are built on first use, from the settings the host registered (`useSettings`), and kept in module-level variables. | A service locator like the ports; the alternative is passing them through every call of the pipeline, the chat and the routes. | `architecture.test.ts` (core reads no environment; each port fails closed) |
| **E2** | Core uses the `Buffer` global (bytes of files, zips, vectors) in the twelve files the test lists. The device supplies it from the `buffer` package (`web/src/core/shims/globals.ts`, which also patches `base64url` into it), so S2's "nothing of Node's" holds for imports but not for this. | Replacing it with `Uint8Array` touches every byte-handling path (zip, export, photo sets, uploads, vectors) and the `Files` port's signatures; that is a project, and the shim is what makes it work today. | `architecture.test.ts` (the list is exact: a file that starts or stops using `Buffer` fails until the list and this row are edited) |
