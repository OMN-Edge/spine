# Configuration

Every environment variable, read from `.env` (copy `.env.example`; `./install.sh -e` writes one with generated secrets) and, for the relay, `relay.env` ([relay.md](relay.md)). A value that names no secret is also passed to each signed-in device. The server checks its own settings and those it passes to devices at startup and lists every problem ([setup.md](setup.md#when-it-will-not-start)); the provider's (which one, its key, Vertex's endpoint, region and project, for the models and the embeddings) are the relay's, which checks them when it starts.

| Variable | Purpose |
|---|---|
| `ANTHROPIC_API_KEY` | Claude API key, on the relay (required when its `SPINE_LLM_PROVIDER=anthropic`); the server holds no model credential |
| `SPINE_LLM_PROVIDER` | The relay's provider: `anthropic` (default) \| `vertex`. The server ignores it and tells devices `relay` |
| `SPINE_LLM_MODEL` | Model id (default `claude-haiku-4-5-20251001`), in `.env`: a device names it with every call, and the relay refuses one it does not offer |
| `SPINE_LLM_ENDPOINT` | The relay's endpoint. **Required for `vertex`, never defaulted** — residency is a property of the endpoint |
| `SPINE_LLM_REGION` | The relay's provider region (required for `vertex`, e.g. `eu`) |
| `SPINE_LLM_PROJECT` | The relay's GCP project (required for `vertex`) |
| `SPINE_LLM_MODELS` | Other models offered in a picker for "Read page with AI" and "Read whole document": `id` or `id=Label`, comma separated, on the same provider, endpoint, region and project unless an entry names its own region (`id|europe-west4=Label`). The default model is always first; an id not listed is refused (400) |
| `SPINE_LLM_MAX_TOKENS_CONTINUATION` / `_EXTRACTION` | Output caps (1024 / 16384). `SPINE_LLM_MAX_TOKENS_PAGE` (16384) caps a page reading. All are ceilings: only generated tokens are billed |
| `SPINE_LLM_CONTEXT_CHARS` | Context window in characters, the only cap on request text (default 300000); longer documents are chunked |
| `SPINE_TRANSLATION` | `off` to stop translating documents (the interface stays translated; content shows in its original language). Default on: translating sends the document's extracted text and the owner's notes to the relay's provider (SECURITY.md **M-13**) |
| `SPINE_EMBEDDINGS` | `none` (default) \| `vertex`: embed each document's summary card for related documents and search by meaning. Set in `.env`, which the server passes on as on or off. Endpoint, region and project are the relay's (`relay.env`), from `SPINE_EMBEDDING_ENDPOINT/_REGION/_PROJECT` or its Vertex model settings; **never defaulted**. `npm run check-embeddings` (server/) sends one test sentence with the relay's settings. `SPINE_EMBEDDING_MODEL` (default `gemini-embedding-2`, called with `embedContent`; what the `eu` multi-region serves) and `SPINE_EMBEDDING_DIMS` (768) define the vector space (SECURITY.md **M-15**) |
| `SPINE_CHAT` | `off` removes the chat panel and the recipient's chat on share links. Default on: each question sends the question and the matching documents' summary cards, notes and results (never a page image; the text of a few pages only when the owner asks the assistant to sort an upload, `read_pages`) to the relay's provider (SECURITY.md **M-18**) |
| `SPINE_LINKING` | `off` to stop looking for links between documents (a consultation and the tests it asked for, a follow-up). Default on: it sends the summary cards of up to seven documents per call to the relay's provider (SECURITY.md **M-16**). Links added by hand still work |
| `SPINE_LLM_CONCURRENCY` | Model calls in flight at once (1-16, default 4); DB writes stay sequential |
| `SPINE_LLM_MAX_RETRIES` | Retries inside the adapter (default 2) |
| `SESSION_SECRET` | ≥32 char random string for cookie signing |
| `SPINE_DOMAIN` | Domain nginx serves from (e.g. `spine.yourdomain.com`) |
| `SPINE_LANDING_URL` | Where the "Shared securely via Spine" footer on a shared page links to (`landingUrl()` in `config.ts`). Unset (or anything but an https address or `off`): this instance's own front page, `/`; an https address: that address; `off`: the footer is text. Reaches the recipient's browser through `GET /api/shared/:id/config`, because that core cannot read the server's environment |
| `SPINE_DEMO_UPLOADS`, `SPINE_DEMO_MAX_UPLOADS`, `SPINE_DEMO_MAX_PAGES` | `on` lets a visitor with no account read files of their own in the demo (default off), up to 3 files, the first 5 pages of each (`demoUploads()` in `server/src/config.ts`; a bad number gives the default). Served to the demo's core by `GET /api/demo-relay/config`, with a pass from `POST /api/demo-relay/token` for `demo:<keyed hash of the address>`; the relay's `SPINE_RELAY_DEMO_DAILY_CALLS` (40) and `SPINE_RELAY_DEMO_TOTAL_DAILY_CALLS` (400) are the bound (SECURITY.md **M-39**) |
| `SPINE_OPERATOR_CONTACT`, `SPINE_LEGAL_DIR` | Where the privacy notice, terms and refund policy say to write to the operator (default "the operator of this instance"; the company they name is the seller saved on `/admin/invoices`, only where `SPINE_BILLING` is on), and a directory of your own `privacy.md`, `terms.md`, `purpose.md`, `refunds.md` instead of the shipped drafts in `docs/legal/` |
| `SPINE_OPERATOR_PRIVACY_CONTACT` | Where the privacy notice sends requests about a person's data, when that is not the address for everything else (`SPINE_OPERATOR_CONTACT`: the terms, the refund policy and the foot of every page). Unset, it is the contact |
| `SPINE_OPERATOR_SECURITY_CONTACT` | The `Contact:` of `/.well-known/security.txt` (an address or a link), when that is not the address for everything else. Unset, or not an address, it is `SPINE_OPERATOR_CONTACT`; with neither the file is a 404 |
| | The company at the foot of every page (`Spine is operated by ...`: its name, tax and register numbers, address and the contact) and in the "Legal / Company information" section of the terms (`{{company}}` in the text) is the seller saved on `/admin/invoices`, the same one the invoices name. It is shown only where `SPINE_BILLING` is on and a seller is saved: an instance with billing off names no company |
| `SPINE_REPO_URL` | Optional. Repository URL that `/source`, `/docs` and `/security` redirect to: nginx does it where it is in front (read by `install.sh -n`), and the server does it everywhere else (Caddy, Cloud Run, `routes/pointers.ts`); unset leaves the redirects out |
| `DATA_DIR` | Where the server's database, the vault and the shares live (the server's default is `<repo>/data`, wherever the process starts; core has no default and fails if a host registers none) |
| `SPINE_STORE`, `SPINE_DATABASE_URL`, `SPINE_DATABASE_POOL` | `sqlite` (default; a file at `SPINE_DB_PATH` or `DATA_DIR`) \| `postgres`: the address (`postgres://…`, with `sslmode=require` off this host) and connections per instance (10). The server's store only: records are on the device, so a device or a test of one refuses `postgres`. A Postgres database is backed up by its host, not by `backup.ts` |
| `SPINE_BILLING`, `SPINE_WAITLIST` | Plans and payment (`docs/billing.md`, SECURITY.md **M-45**): `on` gives accounts a three-month trial, a free plan and the paid plans (Essential, Premium and Family), with the operator as the seller and Stripe taking the payment; every Stripe setting below is then required, and `SPINE_INSTANCE=private` refuses it. Off (default) means no plans and only the instance's own ceilings. `SPINE_WAITLIST=on` shows "Tell me when Spine opens" on the front page |
| `SPINE_BILLING_PROVIDER` | Who takes the payments: `stripe`, the default and the only one; any other name stops the start. An account's own row records who bills it |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `SPINE_STRIPE_PRICE_YEAR`, `SPINE_STRIPE_PRICE_MONTH`, `SPINE_STRIPE_PRICE_FOUNDING`, `SPINE_STRIPE_PRICE_ESSENTIAL_YEAR`, `SPINE_STRIPE_PRICE_ESSENTIAL_MONTH`, `SPINE_STRIPE_PRICE_FAMILY_YEAR`, `SPINE_STRIPE_PRICE_FAMILY_MONTH`, `SPINE_STRIPE_PRICE_TOPUP_PAGES` | Stripe's settings (the three prices are needed, Essential's and the family plan's both or neither; the amounts are Stripe's, read from these prices). The key is a secret or restricted key, and its own prefix says the mode: `sk_test_` or `rk_test_` is the sandbox, `sk_live_` or `rk_live_` charges. There is no checkout address to set: Stripe's checkout is Stripe's own page. The relay never gets either secret |
| `SPINE_EFACTURA_MODE`, `ANAF_CLIENT_ID`, `ANAF_CLIENT_SECRET`, `SPINE_EFACTURA_REDIRECT_URI`, `SPINE_EFACTURA_KEY`, `SPINE_EFACTURA_SERIES` | Spine's own link to ANAF's e-Factura (docs/efactura.md), used when `SPINE_INVOICING_PROVIDER=efactura`: ANAF's `test` platform or `prod` (`SPINE_EFACTURA_MODE`, default `test`), the application registered at ANAF (`ANAF_CLIENT_ID`, `ANAF_CLIENT_SECRET`, and `SPINE_EFACTURA_REDIRECT_URI`, an `https` address ending `/api/admin/efactura/callback`), 32 random bytes in base64 that seal ANAF's tokens in the database (`SPINE_EFACTURA_KEY`), the series of the invoice numbers (default `SPN`). Who the seller is is not a setting: an administrator saves the company on `/admin/invoices` (the name, tax number without `RO`, address with the county's code, a sector for Bucharest, a VAT id only for a VAT payer), for e-Factura as for a service, and an invoice made before one is saved waits numbered. `ANAF_CLIENT_SECRET` and `SPINE_EFACTURA_KEY` are secrets the relay is never given |
| `SPINE_INVOICING_PROVIDER`, `SPINE_INVOICING_VAT_NOTE`, `SPINE_INVOICING_EFACTURA`, `SPINE_INVOICING_MAIL`, `BILLYOU_API_KEY`, `BILLYOU_SERIES_ID` | The operator's invoices for payments the provider is not the seller of (docs/billing.md, "Invoices"). `none` (the default) unless `SPINE_INVOICING_PROVIDER` is `billyou` or `efactura`, and only with `SPINE_BILLING_PROVIDER=stripe`; with a live Stripe key it is required (the process does not start without it), and a test key may go without; then `BILLYOU_API_KEY` and `BILLYOU_SERIES_ID` are needed, or the process does not start. The VAT of each invoice, with a service or with Spine's own e-Factura link (`SPINE_INVOICING_PROVIDER=efactura`), is not a variable: it follows the buyer's country and whether the company is registered for VAT, which the administrator sets on `/admin/invoices` ("VAT on invoices"; docs/efactura.md), and `SPINE_INVOICING_VAT_NOTE` only words the art. 310 mention (unset, the law's own; `off`, none). `SPINE_INVOICING_EFACTURA` (`on`, default `off`) also sends each invoice to ANAF; `SPINE_INVOICING_MAIL` (default `on`) has the service mail it to the buyer; with `off` Spine's own "your invoice is ready" mail goes instead. Who the invoices are made out by is not a variable for a service: the administrator sets it on `/admin/invoices` (docs/billing.md). `BILLYOU_API_KEY` is a secret the relay is never given |
| `SPINE_FAIR_USE_FILE`, `SPINE_ALERT_EMAIL` | The hidden fair-use ceilings and what the operator is told by (docs/billing.md): `SPINE_FAIR_USE_FILE` names a JSON file (default `fair-use.json` in `DATA_DIR`) that sets, for each plan (`trial`, `premium`, `family`), the monthly and yearly ceilings, the `watch` thresholds and the `prices` the AI cost is estimated from; it is read again within half a minute, so a change needs no release and no restart, and a value it gets wrong keeps the built-in one. An administrator can also change any of these values on the admin page: they are kept in the database, apply to every instance and are the last word over the file (so the file may stay as the starting point, a secret mounted on Cloud Run). The plans the file may name are `trial`, `free`, `essential`, `premium` and `family`. `SPINE_ALERT_EMAIL` is where an account that passes about 15 euros of AI cost in a month, or 80% of a ceiling, is reported (the log has it as a warning either way). Never shown to a user |
| `SPINE_NUDGE_DAYS` | The starting value of a setting the admin page can change (docs/billing.md). Days between the reminders to add the documents of an appointment, 7 to 365; unset or 0 sends none. Needs a mailer (docs/billing.md, "Mail about using Spine") |
| `SPINE_AI_BUDGET_EUR` | The starting value of a setting the admin page can change (docs/billing.md). What the operator is willing to spend on AI in a month, in euros: the instance's estimated cost (`plans/cost.ts`) is watched hourly by the jobs and the operator is told once each at 50%, 80% and 100% of it, in the log and, with `SPINE_ALERT_EMAIL` and a mailer, by mail. Unset: nothing is watched |
| `SPINE_OBJECTS`, `SPINE_GCS_BUCKET`, `SPINE_GCS_PREFIX` | Where the sealed bytes (the vault's objects, a share's copies) are kept: `filesystem` (default; files under `DATA_DIR`) \| `gcs` (a Google Cloud Storage bucket, reached as the process's own identity, no key file; `SPINE_GCS_PREFIX` puts one instance's objects under a prefix). A bucket's versioning or soft delete is then their backup (SECURITY.md **M-46**), and `backup.ts` mirrors no files |
| `PORT` | Fastify listen port (default `3000`) |
| `SPINE_PARSER` | `text` (default: the PDF's own text layer; nothing leaves the host; `sidecar` is the old name) \| `ocr` (text layer, then local Tesseract; nothing leaves) \| `multimodal` (a vision model reads every page) \| `hybrid` (text layer first, then local OCR unless `SPINE_OCR=off`, then a vision model for the pages still unread) |
| `SPINE_MULTIMODAL_ENABLED` | `true` to allow page images to be sent to the LLM provider. **A second switch on purpose**: `multimodal`/`hybrid` without it refuse to start |
| `SPINE_OCR` | `off` skips local OCR in `hybrid`: a page with no text layer goes straight to the model, and Tesseract is not needed (default on) |
| `SPINE_TEXT_LAYER_MIN_CHARS`, `SPINE_OCR_MIN_CONFIDENCE`, `SPINE_OCR_MAX_LOW_SHARE`, `SPINE_OCR_LANGS` | `hybrid`'s screening thresholds (50 / 85 / 0.10) and Tesseract languages (`ron+eng`; the packs ship with the web app). First guesses: tune from the `page routed` lines in the browser console |
| `SPINE_REGISTRATION` | `operator` (default: accounts come from the CLI) \| `open` (signup with email verification; **refuses to start without a mailer**) \| `approval` (people ask for an account and it waits for the administrator; needs no mailer, SECURITY.md **M-44**) |
| `SPINE_EMAIL_2FA` | `off` (default) \| `required`. An account with no authenticator app may choose a six-digit code sent to its address as its second step, from the account page; `required` makes that the floor: every account with no authenticator is sent the code after its password, and cannot turn it off. An enrolled authenticator app is asked for instead. Passkey sign-in does not ask for it. **Refuses to start without a mailer** (SECURITY.md **S-20**) |
| `SPINE_MARKETING_EMAILS` | Addresses that may read the operator's numbers (docs/billing.md) and change nothing: the marketing role. Comma separated; `SPINE_ADMIN_EMAILS` may read them too |
| `SPINE_INSTANCE`, `SPINE_ADMIN_EMAILS` | `private` labels the deployment as private (front page, sign-in, `/trust`) and refuses `SPINE_REGISTRATION=open`; default `public`. `SPINE_ADMIN_EMAILS` (comma separated) are the signed-in addresses that use `/admin`, the operator's page outside the app: they decide the accounts waiting under `approval`, read the numbers and change the settings and the hidden ceilings (the changes need the password typed in the last ten minutes); the CLI needs none (SECURITY.md **M-44**, **M-54**) |
| `SPINE_MAILER` | `none` (default) \| `brevo` |
| `BREVO_API_KEY`, `SPINE_MAIL_SENDER` | Required for `brevo`. The sender has no default: pick a neutral name, it is visible in the recipient's inbox |
| `SPINE_TRUSTED_PROXIES` | Comma separated addresses of a proxy that is not on this host and whose `X-Forwarded-For` is believed (the Compose proxy); loopback is always trusted; a wide range or `true` stops startup (`trustedProxies()`, **S-31**) |
| `SPINE_TRUSTED_HOPS` | `1`, `2` or `3`: where the platform's own front end is the proxy and has no address to name (Cloud Run), how many entries of `X-Forwarded-For`, counted from the server's end, are the platform's. With 1 (Cloud Run reached directly, a domain mapping) the client is the last entry, with 2 (a load balancer in front of Cloud Run) the one before it, and what a client wrote earlier is ignored. It is refused beside `SPINE_TRUSTED_PROXIES` (SECURITY.md **S-31**), and needs `SPINE_EDGE_SECRET` unless the count is 1 and `K_SERVICE` is set, which Cloud Run does |
| `SPINE_EDGE_SECRET` | At least 32 characters (`openssl rand -base64 48`): the value the load balancer in front of the server adds as the request header `X-Spine-Edge`. A request that does not carry it is not believed about where it came from: its `X-Forwarded-*` headers are dropped and its address is the one it connected from. Required with `SPINE_TRUSTED_HOPS` and refused without it (SECURITY.md **S-68**) |
| `SPINE_SERVER_HEADERS` | `off` (default) \| `on`: the server sets the security headers (content security policy, HSTS, `X-Frame-Options`, `nosniff`, referrer and permissions policies, no-store on `/share/`) and refuses a path with a dot-file in it except `/.well-known/`, as Caddy and nginx do. `on` where no proxy of ours is in front (Cloud Run); off behind Caddy or nginx, which would send a second copy. `headers.test.ts` holds that the text is theirs |
| `SPINE_LIMITS` | `memory` (default) \| `store`: where the limits on sign-in, sign-up, recovery, sharing and the rest are counted. `memory` is per process, exact for one instance; `store` is the accounts database, one count for every instance, which any deployment with more than one needs, or each instance would allow what the limit says (SECURITY.md **S-66**). A write to the database per limited request |
| `SPINE_JOBS` | `internal` (default) \| `external`: where the hourly work runs (ended shares, card and due reminders, ended sign-ins, unconfirmed accounts, ended limit windows). `internal` is the server's own timers, for a machine that is always on; `external` starts none and `node dist/jobs.js` is run hourly by something outside (a Cloud Run job), as an instance that scales to nothing does not keep time. Safe from any number of instances at once |
| `SPINE_RELAY_DOMAIN`, `COMPOSE_PROFILES=relay` | The relay on this machine: its own hostname (`SPINE_RELAY_URL` is then `https://<it>`), read by `install.sh -r`/`-n` and Caddy, and the profile that starts Compose's `relay` service. Its provider key is in `relay.env`; it listens on `SPINE_RELAY_HOST`/`SPINE_RELAY_PORT` (`docs/relay.md`) |
| `SPINE_RELAY_DATA` | Compose only: the volume the relay mounts at `/data`. Default `data`, the server's, so that the relay opens its SQLite database; with `SPINE_STORE=postgres` set `relay-data`, an empty volume of its own. (`install.sh -r` makes the same choice for the systemd relay from `SPINE_STORE`) |
| `SPINE_RELAY_URL`, `SPINE_RELAY_SECRET` | The relay a device sends model calls to (https, or `http://localhost` to try one) and the secret (32+ characters) shared with it, which signs the ten-minute passes `GET /api/relay/token` gives. Unset: a device cannot call a model. The relay's own settings, including the store its daily count lives in, are in `docs/relay.md` (SECURITY.md **M-35**) |
| `SPINE_TRUST_ANCHORS_DIR` | A directory of certificates (`.pem`, `.crt`, `.cer`, `.der`) the operator trusts as authorities for digital signatures; served at `GET /api/trust-anchors`. With them a signer whose certificates chain to one is filed `verified_signature` (SECURITY.md **S-23**); without, a signature is a label. Nothing ships by default: pick them yourself (for Romania, the qualified trust service providers on the EU trusted list) |
| `SPINE_VAULT_MAX_MB`, `SPINE_VAULT_MAX_OBJECT_MB`, `SPINE_VAULT_MAX_OBJECTS` | What one account may keep in its vault, sealed objects only: bytes, bytes in one object, and how many objects (default 5120, 100 and 50000); a bad value gives the default |
| `SPINE_MIN_FREE_MB` | Free space on the data disk that sealed writes must leave (default 1024; 0 turns it off). Below it a save, a share or a page image is refused with `storage_low` until there is room, so the accounts database and the backup keep theirs. Not asked of a bucket |
| `SPINE_MAIL_MAX_PER_HOUR`, `SPINE_SIGNUPS_MAX_PER_HOUR`, `SPINE_WAITLIST_MAX` | Caps on all sources together, beside the per-source and per-address limits: mails an hour to addresses that are not accounts (default 120), new sign-ups an hour (60), addresses on the waitlist (20000). A flood that spreads over many sources reaches them and then asks people to try again later |
| `SPINE_SHARE_READ_MB_PER_HOUR` | How much of one share's sealed copy or page images one source may read in an hour, in MB (default 2048); past it the answer is 429 `read_budget` |
| `SPINE_MAX_CONCURRENT_READS` | How many reads of sealed objects one account, or one source of a share, may have open at once (default 8); a read is streamed, so each holds little memory, but a few dozen slow ones would starve a small host |
| `SPINE_SHARE_MAX_MB`, `SPINE_SHARE_MAX_TOTAL_MB`, `SPINE_SHARE_MAX_LIVE` | What one account may keep as sealed shares: one object (default 100 MB), all live shares together (1024 MB) and how many are live at once (50); a bad value gives the default (`sharedLimits()` in `server/src/config.ts`) |
| `SPINE_GEOIP_DB`, `SPINE_GEOIP_URL` | The country a share was opened from is read from a country file that `server/src/geoip-update.ts` downloads (from `SPINE_GEOIP_URL`: https, or http to this machine, default the ip-location-db release on GitHub): `data/geoip/country.mmdb` on a machine with a disk, refreshed daily before the backup, and where the process keeps no file (`SPINE_STORE=postgres` with `SPINE_OBJECTS=gcs`, `server/src/local-files.ts`) one object a day in the bucket (`geoip/country-YYYYMMDD.mmdb`), refreshed by the hourly job at most once a day and read into memory by every instance, which finds a newer one within ten minutes. `SPINE_GEOIP_DB` names a `.mmdb` country file of your own instead, and nothing is downloaded (`server/src/geo.ts`) |
| `SPINE_HOST` | Interface Fastify binds (default `127.0.0.1` — nginx is the only public listener) |
| `SPINE_BACKUP_DIR` | Snapshot + vault mirror target (default beside `data/`; set it to removable or network storage to survive media loss) |
| `SPINE_BACKUP_KEEP` | Snapshots to retain (default `7`) |
| `SPINE_BACKUP_TRASH_DAYS` | Days an object the vault removed stays in the backup, in `vault-removed/` (default `7`; `0` drops it at once); an account's are removed when it is deleted |
| `SPINE_SESSION_IDLE_HOURS`, `SPINE_SESSION_DAYS` | A sign-in ends after this long unused (24) or this long in all (14 days); a bad value gives the default (SECURITY.md **M-27**) |
| `SPINE_SKIP_AUDIT` | `1` lets `install.sh -b` build despite a high or critical dependency advisory (offline builds); default is to stop (**S-32**) |

`SESSION_SECRET` (≥32 chars) is validated at startup and by `install.sh -s`: a missing, short or placeholder value stops the process rather than falling back to a default (SECURITY.md **P3**). There is no shared password: users sign in with an email and their own password.
